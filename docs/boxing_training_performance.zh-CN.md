# CPU 物理与 GPU 策略的训练性能

本次优化面向原生 MuJoCo CPU 物理 + CUDA PyTorch / ONNX Runtime 的独立拳击训练环境，不需要 Warp、Isaac 或系统升级。

## 已实现的优化

- 将物理状态字段打包传输，保留 float64 状态精度和可写的关节状态视图。
- 一个 20 ms 控制周期包含四个 5 ms 物理子步。关节目标保持不变时，只在周期起点同步输入、终点同步状态；每个子步仍读取接触力并交给正式裁判。没有跳过冲量采样、修改奖励或比赛时间。
- `--lower-cuda-graphs` 将冻结底层控制器的前向运动学计算捕获为 CUDA Graph，减少大量小 CUDA 算子的 Python 调度。它不捕获 ONNX 循环缓存，不改变模型权重、精度或缓存重置逻辑。CPU 路径保持普通执行。
- `--physics-threads N` 可让独立的 MuJoCo 世界在多个 CPU 工作线程中步进；每个世界有独立模型和状态，读取裁判数据前等待全部线程完成。默认 1，线程池随环境关闭。

两个可选开关会记录在运行目录的 `environment.json`。CUDA Graph 输出缓存只供当前调用使用；若输入形状、类型、设备或流改变，会拒绝重放。

## 使用方式

在已有训练命令上增加 `--lower-cuda-graphs`，并用短实验选择 `--num-envs` 与 `--physics-threads`。例如：

```bash
--num-envs 64 --physics-threads 4 --lower-cuda-graphs
```

增加环境数会增加每次 PPO 更新的样本数。24 步采样时，8 环境是 192 条，64 环境是 1536 条；不能把相同更新次数解释为相同训练预算，也不能从吞吐提升推断得分提升。

不要在正在运行的进程目录内覆盖源码。原训练继续使用启动时的独立代码快照。修改环境数后应通过 `--policy-checkpoint` 建立新训练阶段；这不同于恢复优化器、课程和训练计数的 `--resume`。

## node02 实测（2026-10-31）

RTX 3090、PyTorch 2.6.0+cu124、MuJoCo 3.5.0、ONNX Runtime 1.22.0。GPU 1 测试，GPU 0 的原训练继续运行，因此属于共享节点短基准。各配置从同一个策略检查点开始，种子 43，站立距离课程；运行 20 次实际 PPO 更新，以第 4 至第 20 次更新的计数差和耗时差计算吞吐，排除初始化、前四次更新和最终保存。未开启性能分析器。

| 配置 | 秒/更新 | 学习方样本/秒 | 相对原配置 |
| --- | ---: | ---: | ---: |
| 原版，8 环境 | 2.553 | 75.20 | 1.00× |
| 优化版 + FK CUDA Graph，8 环境，1 线程 | 2.245 | 85.53 | 1.14× |
| 优化版 + FK CUDA Graph，32 环境，1 线程 | 4.644 | 165.39 | 2.20× |
| 优化版 + FK CUDA Graph，64 环境，1 线程 | 7.679 | 200.03 | 2.66× |
| 优化版 + FK CUDA Graph，64 环境，4 线程 | 6.551 | 234.47 | 3.12× |

这些数字是短测吞吐，不是正式得分改善，也不表示完成相同更新次数所需时间缩短。64 环境单线程测试的一次 `nvidia-smi` 显存读数为 2575 MiB；GPU 瞬时利用率不能作为平均利用率。

当前测试中，64 环境、4 线程加 CUDA Graph 的吞吐最高，可用于下一阶段训练；没有穷举所有批量和线程数。原 4096 更新任务没有被替换或重启。

## 验证边界

测试覆盖：独立原生 MuJoCo 步进、单线程/多线程逐步轨迹与约束力一致、局部重置与外力扰动、每个物理子步的接触历史、正式冲量门槛，以及 CUDA Graph 在变化输入和局部重置后的 FK 数值一致性。实际训练短测只能证明该运行配置可执行和吞吐量，不能代替完整比赛质量评估。

本地相关回归 45 passed、2 CUDA 项跳过；node02 CPU/CUDA 专项 25 passed（含这两个 CUDA 项）。新文件 Ruff 检查与修改文件格式检查通过；存量文件的完整 lint 仍含既有告警。

## 其他 GPU 物理方案

[MJX-JAX](https://mujoco.readthedocs.io/en/latest/mjx.html) 可以不依赖 Warp，在 GPU 上批量运行物理；官方也提醒单场景可能比原生 CPU MuJoCo 更慢。这不是切换一个设备参数：需要迁移状态、接触力和逐子步裁判接口，并验证场景支持和数值差异。

node02 的 glibc 2.27 与 Python 3.11 限制可安装的 JAX/JAXLIB wheel；不能仅凭显卡型号断言兼容。若继续迁移，应使用独立个人环境验证，不修改当前可用环境。当前提交没有实现或验证 MJX 后端。
