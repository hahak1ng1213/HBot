# kangning-037：1.5 倍速拳法与距离门控

这次实现的目标是：冻结 HoloMotion 底层，格挡接近时首次进入骨盆水平距离 0.65 m 内即锁定攻击状态，之后只有超过 1.5 m 才退回格挡接近；攻击状态下面向前方的对手循环跟踪 kangning-037 的 1.5 倍速拳法。入口是 `holoboxing.training.skills.train_fixed_punch`，使用现有 PPO 训练五点目标的小幅修正。

当前交付是训练、基线和评估代码。真实原始动作已完成重采样验证，合成 MuJoCo 场景已完成 PPO 更新、保存和加载测试。此前 v3 已使用完整赛事资源和冻结底层完成训练、录像检查；这些运行结果不代表新的 v5 配方已经学会有效命中。这里的 teacher 带有显式动作相位和参考输入，不能直接作为比赛要求的 `[1097] -> [225]` ONNX 提交。

## 1. 行为如何实现

核心实现：[`fixed_punch.py`](../holoboxing/training/skills/fixed_punch.py)。

| 方法 | 作用 |
| --- | --- |
| `geometry()` | 计算双方骨盆 XY 平面距离，以及对手方位与己方骨盆前向的夹角 |
| `attack_gate()` | 根据上一步状态和两个距离门槛锁定攻击状态；不依赖模型是否学会惩罚 |
| `_prepare()` | 保持距离状态记忆，独立判断前方出拳条件；仅在距离状态切换或回合重置时清零拳法相位 |
| `references()` | 移动时生成步伐、转向、防守目标；出拳时生成 kangning-037 的五点目标及关节监督 |
| `step()` | 限制 PPO 修正幅度；移动时屏蔽双手的出拳修正；调用冻结底层和官方裁判 |
| `cyclic_points()` | 动作循环与末尾到开头的平滑衔接 |
| `task_reward()` | 计算下文的全部训练奖励 |
| `training_start_poses()` | 训练时混合近距离拳法与远距离、多方位接近场景 |

v4 使用两个不同距离门槛，避免在同一个门槛附近反复重启拳法：

- 从格挡接近进入攻击：距离严格 `d < 0.65 m`。恰好 0.65 m 不触发首次进入。
- 已进入攻击时保持：`d <= 1.50 m`，包括恰好 1.50 m。0.65–1.50 m 范围内不会重置拳法相位或重新做进入过渡。
- 只有 `d > 1.50 m` 才在下一次 50 Hz 控制更新退回格挡接近；再次靠近需满足 `d < 0.65 m`。
- 朝向与距离状态分开：实际出拳仍要求对手在前方，即 `|theta| < 90°`。对手转到侧后方时保留攻击状态与拳法进度，暂时格挡、原地转向；回到前方后平滑恢复同一拳法进度。朝向变化不会退回接近状态。
- 移动的理想停止距离仍为 0.56 m。未进入攻击时，即使距离在 0.65–1.50 m，也继续格挡接近；进入攻击后继续逐步对准对手。
- 回合终止或无效仿真重置会清除旧回合的状态记忆；新回合重新按 0.65 m 门槛判断。

朝向默认以骨盆局部 X 前向为准；`--guard-offset-deg` 支持固定偏角校准，未自动从动作中推断发力轴。训练和评估必须使用相同偏角。

`--movement demo` 默认采用已审计的 kangning-010 第一个前进片段（原始帧 `[85,275)`），按其实际前进轴调整根部位移；靠近停止距离或未朝向对手时降低前进量，并生成转身目标。双手使用骨盆局部坐标 `(0.18, ±0.12, 0.34) m` 的抬高、收拢格挡目标；手腕朝向从 037 中按手腕位置误差及肘部横向外展超过 0.18 m 的代价共同选择，随骨盆平移和转动，不播放拳法。

`--movement explore` 使用 037 初始静态姿势作为移动起点，由 PPO 探索骨盆和脚部目标修正；双手仍维持防守。它是需要独立训练的备选模式，不会自动把已经失败的示范步伐当作成功而切换。

移动时骨盆位置修正每轴最多 0.12 m、脚部每轴最多 0.16 m，双手独立修正为零。出拳时骨盆和脚部每轴最多 0.015 m、双手每轴最多 0.06 m。旋转修正的旋转向量各分量限制为 0.15 rad。所有修正先经过 `tanh`；训练概率使用修正前的高斯样本。

模式切换使用 10 个控制步（0.20 s）的平滑过渡；出拳循环末尾另加 20 步（0.40 s）的恢复桥接。移动循环累加源片段的净位移，避免每轮把根部目标拉回原点。桥接属于新增过渡，不是原始示范。攻击因距离超过 1.5 m 中断后，下次从裁剪后拳法段的起点重新进入；仅因朝向暂停则保留相位。状态切换只更新参考，不调用物理重置；从当前实测位姿平滑过渡。

距离门控约束的是新下发的出拳目标。已经发生的手臂运动仍有惯性，并需要连续回收到防守姿势；这不意味着物理手腕速度能瞬间归零。1.5 m 是退出攻击状态的门槛，不是物理拳长；骨盆距离也是攻击范围的代理量，实际命中仍需官方接触证据。

攻击参考的全局朝向以每秒最多 0.6 rad 向对手转动，保持源动作的相对拳法及关节轨迹，避免固定世界朝向与新的对准奖励冲突。记录 `elbow_lateral_extent_m`，用于检查实际肘部是否收拢；五点底层不能直接指定肘部，仍需要物理检查。

## 2. 1.5 倍速如何实现

实现位于 [`reference.py`](../holoboxing/training/skills/reference.py) 的 `retime_trajectory()`：

```text
控制频率保持 50 Hz
第 k 个训练参考帧，采样原动作的 1.5*k 帧
位置、关节角：线性插值
根部四元数：SLERP
根部线速度、根部角速度、关节速度：插值后乘以 1.5
五点和身体位姿、速度：由重采样后的关节和根部状态重新 FK
```

对本地真实原始文件的核对结果：1417 帧变为 945 帧；首末采样时刻之差由 28.32 s 变为 18.88 s；对应整数源帧处的位置、关节角及 1.5 倍速度一致。源文件 SHA256 为 `5fb08bf087e8acece4342f2739c06b1c20912ce6e1b3494f02aabcfa40d0301c`，处理前后未变。FK 一致性测试使用合成的同名关节模型，不代表真实机器人已能稳定跟随。

v3 的攻击任务使用原始 50 Hz 帧区间 `[90,1321)`：起止均为拳击准备姿态，排除开头和结尾双臂展开的采集准备动作。保留的 1231 帧经 1.5 倍重采样为 821 帧，首末时间跨度 16.40 s。原始第 0 帧双腕相对骨盆的横向位置约 +0.49/-0.44 m；旧版本反复从第 0 帧进入并循环回第 0 帧，是状态切换张臂的重要原因。裁剪保留原文件及其哈希，源帧区间写入 manifest。

这里没有修改 MP4 播放速度，也没有只改 fps 标签。0.40 s 循环恢复桥接另算，不能把整轮“拳法加恢复”描述为原始整轮严格缩短 1.5 倍。

## 3. 奖励函数

控制周期 `dt=0.02 s`。除官方命中、倒地和无效状态外，下表所有项都乘以 `dt`。格挡接近不领取拳法模仿奖励；攻击状态不领取接近奖励，其中因朝向暂停出拳时领取格挡跟踪奖励；朝向进度和对准奖励始终启用。PPO 使用下面的奖励总和，不再叠加旧训练器的通用攻击奖励。v5 将朝向引导提高到 v4 的 3 倍、拳法上肢跟踪提高到 2 倍，加入无躯干接触惩罚。

记 `K(e,s)=exp(-(e/s)^2)`。RMS 指参与比较的全部分量的均方根；位置单位 m，关节角单位 rad。

| 奖励项 | 权重及表达式 | 目的 |
| --- | --- | --- |
| 接近进度，移动时 | `2.0 * clip((abs(d_old-0.56)-abs(d_new-0.56))/dt,-1,1)` | 仅在格挡接近状态、步初距离 >=0.65 m 时启用 |
| 移动格挡跟踪 | `2.0 * K(wrist_RMS,0.08)` | 保持抬手格挡，避免张开双臂 |
| 朝向进度，移动和出拳均启用 | `1.5 * clip((abs(theta_old)-abs(theta_new))/dt,-2,2)` | 奖励通过移动、转身面向对手 |
| 朝向对准，移动和出拳均启用 | `3.0 * cos(theta_new)` | 越接近正对对手，奖励越大 |
| 超时无躯干接触，全模式 | `-0.5 * I(连续无接触时间 > 5 s)` | 超过 5 秒后每步扣 0.01 分，真实接触后停止扣分 |
| 双腕相对骨盆位置，出拳时 | `4.0 * K(wrist_RMS,0.10)` | 保持 037 拳路，去掉根部平移影响 |
| 双腕旋转，出拳时 | `0.6 * exp(-rotation_matrix_MSE/0.16)` | 跟踪源动作的手腕姿态 |
| 双腕相对骨盆线速度，出拳时 | `1.0 * exp(-relative_velocity_MSE)` | 跟踪加速拳法的速度；进入模式后 10 步才启用 |
| 肩、肘关节，出拳时 | `2.0 * K(arm_joint_RMS,0.35)` | 约束肩肘动作，弥补只有五点目标的不足 |
| 双脚世界位置，出拳时 | `0.8 * K(feet_RMS,0.06)` | 保持示范下肢与支撑位置 |
| 骨盆世界位置，出拳时 | `0.5 * K(pelvis_L2,0.08)` | 限制出拳过程中不必要的整体漂移 |
| 髋、膝、踝关节，出拳时 | `0.5 * K(leg_joint_RMS,0.25)` | 进一步保持示范下肢姿势 |
| 直立 | `0.2 * clip(pelvis_rotation[2,2],0,1)` | 鼓励平衡 |
| 时间成本 | `-0.1` | 每一步的时间成本 |
| 修正幅度 | `-0.02 * mean(action²)` | 尽量少改动示范 |
| 修正变化 | `-0.02 * mean((action-prev_action)²)` | 减少目标抖动 |
| 官方合法 HIT | 每次 `+5`，不乘 dt | 只在本步开始实际出拳，且步末仍在 1.5 m 内、对手处于前方（朝向误差严格小于 90°）时给奖；必须有官方接触命中记录 |
| 倒地 | 每个被判为低姿态的控制步 `-2`，不乘 dt | 惩罚倒地状态；仍由官方裁判决定 KO/回合结束 |
| 无效仿真状态 | 本步总奖励覆盖为 `-10` | 单独计为失败，不允许作为成功命中或正常回合 |

手腕速度误差比较的是“手腕世界速度减骨盆世界线速度”，参考速度由相邻的 1.5 倍速目标帧差分得到；不是角速度完全解耦的局部手腕速度。姿态误差使用旋转矩阵 MSE，不是直接把四元数分量或角度平方相加。

v5 无接触计时从回合开始计起，在移动、攻击和朝向暂停之间持续累计；只有己方拳套/合法手部与对方躯干的真实物理接触才清零。躯干沿用裁判语义（胸腹、torso 和 pelvis），头部、手臂、地面、自身接触不计。低于官方得分冲量阈值的轻触也会清零，但不额外加分；正式命中奖励仍要求官方 HIT。统计汇总全部 200 Hz 子步，避免漏掉控制帧中途接触；回合重置仅清除对应环境的计时。计时加入策略观测，维度由 1355 改为 1356。日志增加 `torso_contact`、`no_torso_contact_s` 和 `no_torso_contact`。

骨盆、脚、关节的跟踪目标保留原示范的小幅变化，没有把腿部关节锁死，也没有把下肢参考全部置零。五点高层控制无法直接命令肩肘关节，因此关节奖励只是改善约束，仍须实测下层能否实现。

进入模式的前 10 步以及循环恢复桥接期间，肩肘和腿部关节奖励关闭，继续使用五点跟踪。这样可避免同时要求“线性插值的五点”和“线性插值的关节”必须具有完全一致的正向运动学。

新增 `capture_transition_state` 选项在环境自动重置前保存实际状态，避免把重置后的位置误当作接近进度或命中状态。原有任务默认不启用此选项。

## 4. 训练与验收

冻结底层使用既有的、经过 bundle 验证的 HoloMotion V2。PPO 只更新 30 维目标修正策略和价值网络，网络隐藏层为 256/128，v5 学习率默认 `1e-4`，裁剪系数 0.2，折扣 0.995，GAE 0.95。v5 每个小批次更新后，计算整个 rollout 上新旧高斯动作分布的解析 KL；超过 0.03 则回退该次模型参数与 Adam 状态、学习率减半（最低 1e-6），结束当前 rollout 的优化。先前通过检查的小批次保留。日志 `ppo_kl` 记录保留策略的解析 KL，`ppo_rejected_kl` 记录被拒绝候选（非有限值用 -1 标识），`ppo_rejected_update` 记录拒绝事件。

当前新配方的蓝方为用户确认的 seed44 / model_1536，使用该检查点导出的 `seed44-update1536.onnx` 作为 `--opponent-onnx`，不启用 `--standing-guard`。冻结源检查点 SHA256：`b5af327c5fc4754d9d3586f5ae96b00f36f5f8f7619753f6e4cb22fb96f9cdc5`。新配方保持原来的 1.5 倍速和 0.65/1.5 m 距离状态切换；奖励加强和短训练通过不代表动作跟踪质量已经验收。

也可用 `--opponent-onnx /path/to/seed49-update2048.onnx` 替换站立蓝方。该模式取消站立目标覆盖，蓝方接收自身的 1097 维观测并输出 225 维目标；ONNX 内的预处理和参数保持冻结，采用单线程 CPU 推理，PPO 仅训练红方。对手文件 SHA256 写入配方并用于评估一致性校验。此接口要求无状态的 `[1,1097] -> [1,225]` 比赛模型。两种对手模式的检查点不能混用。

被动格挡木偶对照使用 `--standing-guard`，不传 `--opponent-onnx`。蓝方保持固定的世界坐标站立目标，双腕采用骨盆局部 `(0.18, ±0.12, 0.34) m` 的收紧格挡位置及从 037 选出的手腕朝向；整段回合中目标不会随受击位移重新定位。蓝方不运行攻击策略，保留动力学与接触反应，因此不是焊死的静态碰撞体。每次回合重置后重新锚定目标，具体格挡姿态写入配方。新对照从头训练 512 轮，红方任务、奖励和 PPO 设置保持不变。

训练重置一半为 0.52–0.58 m、朝向误差 ±10°，另一半为 0.65–2.0 m、朝向误差 ±180°；世界方位随机。保留原比赛重置的关节、根部高度和倾斜。评估从原有比赛重置开始，不使用上述训练分布。

在已配置好的 standalone boxing 环境中，从仓库根目录运行。以下 Bash 命令中的 `SOURCE` 指包含 `boxing_20251226/` 的原始 RoboStriker 目录；`HOLOBOXING_ASSETS` 与 `HOLOBOXING_LOWER` 使用已有资源。输出目录及对应 `.runtime` 目录都必须不存在。

```bash
# 先检查零修正参考在真实底层上的物理行为
python -m holoboxing.training.skills.train_fixed_punch \
  --source "$SOURCE" --output outputs/k037-baseline \
  --movement demo --mode baseline --num-envs 2 --eval-steps 3000

# 新任务训练；按机器能力设置环境数，不默认占用其他进程使用的 GPU
python -m holoboxing.training.skills.train_fixed_punch \
  --source "$SOURCE" --output outputs/k037-train \
  --movement demo --num-envs 8 --updates 2048 --save-every 64

# 使用同一资源、源码、偏角与 movement 配置评估训练结果
python -m holoboxing.training.skills.train_fixed_punch \
  --source "$SOURCE" --output outputs/k037-eval \
  --movement demo --mode evaluate \
  --checkpoint outputs/k037-train/model_002048.pt \
  --num-envs 8 --eval-steps 3000
```

如果示范步伐难以跟踪，另建输出目录，使用 `--movement explore` 重新训练和评估。代码不会混用两种模式的检查点。CPU 网络调试可加 `--device cpu`；物理本身仍为原生 CPU MuJoCo。

独立的无对手拳法训练入口也增加了动作选择和速度参数，可以单独诊断底层是否能执行加速拳法：

```bash
python -m holoboxing.training.skills.train \
  --source "$SOURCE" --skill punch \
  --punch-groups kangning-037 --speed-scale 1.5 --punch-bounds 90 1321 \
  --output outputs/k037-solo --mode train
```

独立拳法 teacher 和带对手任务 teacher 的观测不同，不能直接互相加载权重；当前没有实现跨任务蒸馏或无缝续训。带对手任务直接以同一个 037 参考初始化残差训练。

每次训练保存 `recipe.json`、逐项 `metrics.jsonl`、模型检查点和运行状态。v5 的检查点标识为 `kangning037_range_teacher_v5`，观测和奖励与旧版本不同，本轮独立训练，不混用旧检查点。检查点包含原始数据哈希、速度、环境配方、资源哈希与相关实现源码哈希。新增日志 `attack_mode`（距离锁定状态）、`punch_active`（实际出拳）、`alignment_only`（攻击内转向）、`reference_phase` 和 `mode_changed`，用于区分切换抖动、朝向暂停和拳法推进。评估保存 `evaluation.json`，分别报告官方 HIT 和满足距离/朝向条件的 HIT。必须完整回合、无倒地/无效状态且有范围内官方命中，才把初步攻击门槛记为通过；进程跑完或训练奖励变大都不等于通过。

目前评估覆盖的是站立对手第一阶段，没有证明会追踪移动对手、持续保持全局朝向、反复完整执行整套拳法或达到比赛提交要求。这些需要真实冻结底层的连续录像、距离/朝向曲线和命中记录进一步验收。

## 6. v6 伸拳触达微调（2026-11-05）

第一组从 contact-v5 的 `model_000512.pt` 初始化，训练 **10240 次 PPO 更新**。入口新增成对参数 `--init-checkpoint`、`--init-source-root`：核对原检查点的观测、网络、参考动作、资源、对手和完整源码哈希后，只加载模型参数，重建 Adam；不是恢复旧优化器或仿真状态。学习率显式设为 `1.25e-5`，仍用全 rollout 解析 KL 0.03 的回退保护。蓝方继续冻结 seed44 / model_1536。

`fixed_punch.task_reward` 新增 `punch_reach`，`punch_reach.PunchReachGeometry` 用 MuJoCo 合法碰撞体计算左右拳套到对手胸腹躯干的最近表面距离，不把手腕原点当拳套，也不包含头部或骨盆。测量在自动重置前保存。正向手臂速度扣除己方躯干的平移和转动；对方走过来、自己整身撞过去或拳套停留贴靠，不会单独获得伸拳奖励。

每步新增奖励为 `dt * 4 * max_hand(exp(-max(gap,0)/0.18) * aimed_speed_gate * outward_speed_gate * closing_speed_gate) * upright`。三个速度门依次是 `clip((v_arm_aim-0.05)/0.75,0,1)`、`clip(v_arm_outward/0.3,0,1)`、`clip(v_closing/0.3,0,1)`。仅在已稳定进入攻击、非循环桥接、参考该手正在向前伸出、对手在前方且骨盆距不超过 0.85 m 时启用。官方 HIT 仍每次 +5；没有把几何接近记作命中。

为避免“想打长却被原参考拉回”，正向手腕残差上限从 0.06 m 增至 0.18 m，负向、横向和高度仍为 0.06 m，脚和骨盆的修正范围不变。向对手方向的额外 0.12 m 伸展可免除位置跟踪惩罚，容忍随参考前向速度在 -0.1～0.1 m/s 内平滑退入退出；只适度减弱相应手臂的肩肘跟踪，完整回收时恢复严格跟踪。没有改变 1.5 倍速、0.65/1.5 m 状态锁存或移动格挡。仍不能仅靠伸拳保证在整个 1.5 m 锁存范围内够到对手。

新增验证覆盖真实表面几何、躯干刚体速度剔除、冻结蓝方角色交换、伸拳/回收奖励边界、单侧方向容忍，以及 v5 参数初始化的源码与接口验证。短试通过只证明训练路径可以执行；有效命中数、伸拳长度和连续稳定性仍以正式训练后的比赛重置录像为准。

## 7. v7 自主拳法与完整周期提速（2026-11-05）

入口为 `holoboxing.training.skills.train_free_punch`。红方保留 v6 **9536 轮**策略作为冻结动作基础，新增一个从零输出开始的 30 维修正策略；只有新策略和其价值网络更新。零修正时保留原基础动作目标，移动与转向阶段继续使用原格挡和步伐。攻击阶段允许双腕每轴 ±0.40 m、旋转向量每轴 ±0.8 rad 的调整；拳法不再受到 037 手腕、速度、肩肘模仿奖励的约束。仍有五点控制、动作范围、物理关节极限等约束，因此是受物理接口约束的自主探索。

蓝方同样使用冻结的 `train10240/model_009536.pt`，并从原 v6 源码快照执行原控制器。蓝方保留原 1356 维观测、30 维残差、参考、相位、格挡和模式切换。适配器在原控制器提交动作时取得目标，红蓝一起推进一次物理，再按原 v6 逻辑更新蓝方状态；蓝方奖励不参与优化。每步检查冻结参数，加载时校验模型格式、9536 更新号、参考数据、资源和原源码。新增逐手 HIT 计数只读取裁判诊断，不修改判罚规则。

### 奖励与完整动作

实际奖励在 `free_punch.FreePunchCombatEnv.step`，旧 v6 奖励只用于兼容基础控制器，计算结果不进入 PPO。主要项如下；表中标注“每秒”的项实际乘 `dt=0.02`。

| 项目 | 数值与条件 |
|---|---|
| 官方有效 HIT | 每次 +10；不再用额外状态/朝向门丢弃合法 HIT |
| 受到 HIT | 每次 -1 |
| 命中后完整收拳 | 每手每周期 +0.5～1.5；速度质量与有效周期频率决定额外部分 |
| 接近拳距 | 每秒 `2 * clip((旧距离误差-新距离误差)/dt,-1,1)`，目标骨盆距离 0.55 m |
| 朝向 | 每秒 `cos(误差)`；缩小角度每秒另加 `0.5 * clip(角度改善/dt,-2,2)` |
| 主动伸拳接近躯干 | 每秒最高 +1；基于真实拳套—胸腹表面距离和去掉躯干刚体运动的手臂速度，不依赖原参考出拳相位 |
| 收拳进展 | 每秒最高 +0.4；只在完成伸展后，按双手平均回收速度给有符号奖励 |
| 无有效命中 | 5 秒后渐增，10 秒达到每秒 -0.5；轻触不会清除这个计时 |
| 平衡/双脚 | 每秒 `0.3*直立度-2*(1-直立度)`；双脚跟踪每秒最高 +0.3 |
| 过低身体、抖动与修正幅度 | 过低每秒最多 -4；动作变化与幅度系数分别 -0.1、-0.01 |
| 低姿态、无效仿真 | 低姿态每控制步 -2；无效状态总奖励覆盖为 -10 |

`PunchCycles` 对左右手分别识别：先进入格挡区域，再离开格挡、完成至少 0.20 m 伸展或发生该手 HIT，最后回到距格挡目标 0.12 m 内。完整周期时长必须在 0.25～3 秒之间，且身体稳定。只有该周期中真实命中过的手才获得完成奖励；空挥、一直贴住对手、未收回的拳和超时动作均不能获得这个奖励。空挥也不会重置“有效完整周期”的频率时钟。

### 逐步提速与降低骨盆

目标完整周期依次为 **1.40 → 1.20 → 1.00 → 0.85 → 0.70 秒**。动作越接近当前周期时限，命中收拳奖励越高；当前阶段内的速度加奖有上限。有效完整周期越密集，频率加奖越高。

每 64 个 PPO 更新评估一次：窗口内至少 8 次“命中且收拳完成”、12 次完整动作、低姿态控制帧占比不超过 1%、无无效仿真，才升一级。低姿态超过 3% 或出现无效状态时降一级。未达到门槛就维持阶段，不按训练轮数盲目加速。课程阶段与窗口统计保存在检查点；评估恢复相同目标周期。

策略可主动把骨盆目标降低 **0～8 cm**，双腕目标随之下降，双脚不随骨盆下降；攻击时双脚仍允许最多 1.5 cm 的小幅修正。直立、双脚支撑和过低惩罚引导其选择稳定姿态。是否真正降低物理重心、提高拳速仍须通过训练后录像和物理状态验证。

新策略观测为 1397 维，增加左右手完整周期状态、上次新策略动作、课程阶段和无命中计时；与旧 1356 维策略不能互换加载。默认学习率 `1e-5`，保留整个 rollout 高斯 KL 不超过 0.03 的更新回退保护。新策略零输出初始化，探索标准差初值 `exp(-3)`，优化器从新阶段重新建立。
